# 论文博客制作与排查指南

本文件记录 SuperPoint 精读制作中实际遇到的问题，以及可复用的处理方式。写作原则见 [论文详解技术博客原则](research-blog-style.md)。这里只记录本站实现与已验证经验，不把当前机器的路径或一个脚本的局限当作通用标准。

## 文件与复现约定

| 内容 | 位置 | 要求 |
| --- | --- | --- |
| 正文 | `src/content/blog/<slug>.md` | 问题驱动叙事、分级标题、LaTeX |
| 发布素材 | `public/media/<slug>/` | 压缩图像、SVG、必要的复现源素材 |
| 制作脚本 | `scripts/` | 保留提图、变换、绘图的参数与源码 |
| 通用数学排版 | `scripts/lib/math.mjs` | 正文与自制图共享 MathJax/STIX2 |
| 素材记录 | `docs/<slug>-assets.md` | 原图清单、版本、参数、提示词、复现命令 |
| 临时材料 | 仓库外 | 原始 PDF、整页渲染、截图、缓存 |

不要只手改生成的 SVG。先改源脚本，再重生成与目视验证。生成模型选中的项目素材要复制到仓库，不能让网站依赖个人 `$CODEX_HOME` 下的文件；优化后仍足以复现的源图可以随仓库保存。

文章图片使用语义化结构：

```html
<figure>
  <a href="/HomepageX/media/example/mechanism.svg" target="_blank" rel="noopener">
    <img src="/HomepageX/media/example/mechanism.svg"
         alt="具体说明比较对象、关键变化和结论"
         width="1200" height="700" loading="lazy" />
  </a>
  <figcaption>自制图 1 · 同一图块移动后的定位歧义示意。</figcaption>
</figure>
```

本站 base 为 `/HomepageX/`，媒体与放大链接都要包含它。重新裁图后同步真实 `width`、`height`，以免布局占位比例过时。原图使用原论文编号，自制图按正文顺序编号。

## 原论文图：先检查整页，再精确裁切

先渲染整页确认图的边界，再按页宽高归一化坐标记录裁剪矩形。小字与数据曲线需要足够分辨率；SuperPoint 使用 260 DPI 渲染和高质量 WebP，但不要求其他论文照抄这一数值。以实际文字可读性、细线完整性与体积为准。

可参考 [提图脚本](../scripts/extract-superpoint-figures.py)。它的图号、页码与裁剪参数只适用于 arXiv:1712.07629v4，换论文或版本必须重新测定。

检查所有原图的拼图预览，再单独放大细节密集的图：不能裁掉边缘标签、下半面板或横轴；不要只检查第一张。图表旁原文与图注需读过，尤其核对指标定义、训练／测试设置、失败案例和附录额外实验的条件。

## 已遇到的问题与处理

### 1. 给公式换 CSS 字体，仍然不像论文

原因：反引号里的公式是代码样式；Unicode 上下标、希腊字母与普通文本会触发不同字体回退。修改 `font-family` 不能补出正规的分式、矩阵与数学间距。

做法：把数学内容改为 LaTeX，统一经过 MathJax + STIX2；图内同样生成数学 SVG。中文解释仍保留中文字体。不能因为写了 `Times New Roman` 就声称使用了它，本次环境实际没有该字体。

验证：同时看行内变量、独立公式、矩阵、上下标与自制图，不只检查一个简单的字母。

### 2. Astro 的 Markdown 插件配置与当前版本不匹配

本仓库使用 Astro 7。此次直接设置旧式 `markdown.remarkPlugins` 时，先遇到缺少 `@astrojs/markdown-remark` 的报错，安装后又出现旧配置弃用提示。

本站最终配置保存在 [astro.config.mjs](../astro.config.mjs)：通过 `@astrojs/markdown-remark` 的 `unified()` 显式配置 processor，先运行 `remark-math`，再运行本地数学转换插件。复用现有配置，不为新文章再加一套客户端公式库或 CDN。

验证：构建产物应已经含数学 SVG，不能只剩 `$…$` 文本；检查错误节点和渲染日志。升级依赖后重新核对接口，不把本段当作永久不变的上游 API。

### 3. 图内公式只显示一半，剩余符号跑到左上角

原因：MathJax 4 默认可将行内公式拆成多个 SVG，并在中间插入断行标记。若后处理假定只有一个 SVG，再用正则截取，会把多个片段错误嵌套。

做法：当前共享渲染器明确配置 `linebreaks: { inline: false }`，保证现有嵌图流程使用单段输出；使用 `fontCache: 'none'` 保持字形路径自包含。若未来需要真正的多段公式，应完整处理输出结构，不能取消配置后继续沿用单段截取逻辑。

验证：检查含等号、加减号、长函数和上下标的公式；实际将 SVG 渲染成图片，确认没有散落在画布原点的符号。

### 4. 带撇号的公式报 `Misplaced &`，或中文与公式粘在一起

原因：Python HTML 转义可能把撇号写成 `&#x27;`；直接将该实体送入 TeX，`&` 会被解释成对齐符。另外，SVG 普通文本会折叠空格，使按宽度预留的中英文间隔消失。

做法：将 HTML/XML 实体还原成原始公式后再送入渲染器，输出时再正确转义；当前后处理已处理撇号实体。混排普通文本使用 `xml:space="preserve"`，定位时考虑 `viewBox`、字号、基线和起始／居中／右对齐锚点。

当前脚本对普通文本宽度使用近似估算，不能把“没有报错”当作没有重叠。复杂长标签优先拆成明确定位的文本与公式，再目视检查。

### 5. SVG 的线条和彩点都在，照片却是空白

此次包含 WebP data URI 的 SVG 在所用 Sharp/librsvg 渲染路径中没有显示照片。浏览器与离线渲染器对嵌入图像格式、引用方式的支持不一定一致。

做法：本例改为在 SVG 内嵌 JPEG data URI，并使用带命名空间声明的 `xlink:href`；PNG 也可按需评估。发布的源素材仍可以是 WebP。此处是已验证的兼容处理，不是说所有 SVG 渲染器都不支持 WebP。

验证：既看离线栅格化结果，也看网页里的真实图像，不能把空白区域误认为变换本身的结果。

### 6. 写实的“变换后图片”不等于正确的几何变换

分别让生成模型画原图和变换图，会悄悄改变物体、纹理与遮挡，使所谓对应关系失去依据。

做法：固定一个源图和目标画布；点按前向矩阵投影，图像用逆矩阵回采样；插值和边界填充值明确，有效区域按同一变换生成。保存矩阵、源坐标、图像尺寸与采样方式。坐标单位变化后必须转换矩阵，不能直接复用像素坐标下的系数。

验证：选几个点手算投影，核对图中标记；检查掩码、可见范围与正文数值。把“生成源场景”和“程序计算变换”写清楚，不把二维扭曲误说成真实三维相机重拍。

### 7. PDF 渲染程序存在，但运行时报动态库版本错误

此次 PATH 中一个 bundled `pdftoppm` 要求更高版本的 GLIBC，系统 `/usr/bin/pdftoppm` 可以运行。

做法：先确认实际调用的可执行文件及报错；如已有兼容的系统工具，明确使用它。不要为了裁论文图去修改系统库。路径按当前环境核实，不能无条件要求所有机器使用同一绝对路径。

### 8. 构建已更新，浏览器却还是旧文章

此次开发进程曾出现模板已更新、内容仍旧的情况；刷新页面和触碰 Markdown 文件没有解决，重启该仓库的本地 Astro 开发进程后恢复。不能仅凭浏览器旧内容断定源文件修改失败，也不要把原因未经验证地归为某个具体缓存实现。

处理顺序：检查源文件 → 检查 `dist/` 构建产物 → 确认浏览器 URL、服务端口和进程工作目录 → 刷新 → 必要时重启已确认的本项目预览进程。不清理无关缓存，不停止不属于本项目的服务，不把旧页面截图当作新版本的验证证据。

### 9. 请求手机视口，不代表实际页面已经变窄

做法：设置视口后读取真实 `innerWidth`，再检查 `scrollWidth`、目录开合与长公式容器。此次最终在 390px 视口验证；不能只根据工具调用成功就宣称测过手机。

检查目录能展开、跳转后收起；长公式和表格只在自身区域滚动，页面整体不溢出。验证结束恢复临时视口设置。工具无法切换时如实记录限制。

## 复用数学与绘图流程

[数学渲染器](../scripts/lib/math.mjs)可供新的正文和绘图脚本复用。[图内数学后处理](../scripts/typeset-figure-math.mjs)目前**固定处理 `public/media/superpoint/`**，并只识别简单 `<text>` 中的 `$…$` 标签，不是任意 SVG 的通用转换器。

用于新文章时，先将目标目录做成明确参数或编写相应调用，再验证；不要直接运行后误以为新目录也已处理。当前 SuperPoint 重生成命令见 [素材记录](superpoint-assets.md)。顺序始终是：源脚本绘图 → 数学排版 → 栅格化目视检查 → 页面检查。

## 交付检查记录建议

在文章素材文档或交付记录中保留实际结果，不仅写“已测试”：

- 原图清单逐项覆盖情况、未收录项与原因；自制图的定义和复现入口。
- 本地图片、大图链接、alt、真实尺寸、自制图编号、目录锚点与重复 ID 检查。
- 数学渲染无错误节点，图内无未处理公式；复杂公式和全部新增图片已目视检查。
- 原图数据、坐标变换、人工数值与正文一致；训练、推理、消融和第三方实现不混用。
- 实际运行的构建／类型检查结果；桌面、手机真实宽度与溢出检查；未能完成的检查。
- 仅本地修改、已提交、已推送或已发布的真实状态，不混为一谈。

优先执行与改动相关的验证。纯文档整理检查链接、路径、语义和差异即可；不为了填检查清单而重跑无关任务。
